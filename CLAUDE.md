# CLAUDE.md

**DIY Inventory**: property inventories, check-ins, check-outs and inspections done on a phone, for tenants, landlords and small agencies (£30 per report; no subscription). **The business does not charge VAT: never add or mention VAT anywhere (prices, totals, JSON-LD, emails, the app).** The app and the PDF carry no agency name ("DIY Inventory"), and each report is titled after its property: `reportTitle()` → "Check-In – 5 Dudley Court, London W1H 5QA" (or Check-Out, or Inspection for interim and renewal inspections; `inspectionKind()`). The managing agent field is optional and blank by default; it only appears on the PDF cover when filled in. Deployed on Railway from this repo (`npm start`, health check `/healthz`).

## Layout

- `public/index.html` is the whole client: HTML, CSS and one inline `<script>`. There is no build step, no bundler and no framework. Edit the file directly.
  - jsPDF 2.5.1 is loaded from cdnjs as a UMD script (`window.jspdf.jsPDF`). `buildPdfBlob(state, onProgress)` builds the report in the browser (A4 landscape, clerk report format).
  - The draft is kept in IndexedDB on the tenant's device. When a report is finished, `submitReport()` quietly saves a copy of the PDF with `POST /api/reports` (once per report: `state.submittedId`; retried when back online), so it is never lost. Finishing (signed and declared) then sends it straight away with `sendToAgent()` → `POST /api/reports/:id/send`, which marks it sent (`state.sentAt`), alerts the owner (ntfy) and, if `REPORT_TO_EMAIL` is set, emails it there. No extra tap is needed: the finished screen's button only shows the progress, or **Try sending again** if it failed; it also retries when the connection returns or the report is reopened. Nothing else is stored on the server.
  - The PDF is delivered as a plain browser download (object URL + `<a download>`). Do not add `claude.*` / `window.claude` calls. The client only talks to this server's `/api/*` endpoints.
  - `preparePdf()` builds the PDF once per finished report and keeps it, so `savePdf()` / `openPdf()` / `sharePdf()` run straight from the tap (phones block downloads that start after the async build). Share uses the Web Share API only where `navigator.canShare` accepts files. A finished report stays in IndexedDB and reopens on the done screen until a new inspection is started.
  - Every photo in the PDF (cover, keys, meters, rooms) is drawn uncropped with `drawFitted()` from a smaller copy (`shrinkPhoto()`: 900 px, 1400 px on the cover). There are no full-size pages in the PDF: each photo, and its View link in the "Index of photographs" at the end, links to `/p/<photoKey>/<n>`, which shows it full size. `photoKey` is random per report (`ensurePhotoKey()`), `n` is the photo's order in the PDF; `buildPdfBlob(state, onProgress, out)` returns that list in `out.photos`, and `submitReport()` uploads the full-size photos after the PDF (`uploadPhotos()`, `state.photosUploaded`).
- Home-screen icon: `public/icons/` (drawn in `icon.svg`, exported to `apple-touch-icon.png` 180, `icon-192.png`, `icon-512.png`, `favicon-32.png`) and `public/manifest.webmanifest` (name "DIY Inventory", `display: browser` so it opens in the normal browser, keeping the camera and PDF downloads as they are). Re-export the PNGs if `icon.svg` changes.
- Look (app): beige and navy like the website (tokens in the "2026 refresh" block at the end of the `<style>`, `--grad` navy; dark mode navy with lighter navy buttons and camel accents). The block overrides the base tokens and components (`--grad`, Plus Jakarta Sans headings, gradient hero `.masthead`, borderless cards, filled inputs, pill buttons; light and dark).
- **The PDF's design** (`buildPdfBlob`) matches the website, not a clerk's table: palette `C` (beige paper, navy ink and `accent`, as on the website) and `COND` (a colour per condition), Times for titles (`serif()`) and Helvetica for text (`set()`), hairline rules instead of filled heads (`hr()`, `table()`, `banner()`), condition labels (`pill()`) and stacked condition bars (`condBar()`). Cover: the front of the property bleeds top right, the address in serif on the left, the condition of every item and the totals at the bottom left, details under the photo. Then Contents, **At a glance** (totals, every item's condition, a row per room with its condition bar), the changes (check-outs), information pages, keys, meters (reading in large type), detectors, property details, then each room: `roomHeader()` (summary strip and condition bar) and every item as a card, two to a row (`measureCard()`/`drawCard()`: its photo, extra photos as thumbnails, condition label, description, details and, when compared, how it was then and what changed), a summary panel and the room's general views. Declaration, index of photographs. Photos are still numbered in the order drawn and linked (`registerFullSize()`/`linkPhoto()`).

Every site page has a 1200×630 share image (`public/img/og.jpg`, made from the hero text and a report page; `summary_large_image`) and `lang="en-GB"`.
- **Website** (for everyone without access, no agency name): `views/layout.html` (header with menu, a `<details>` menu button on phones, footer) around one page from `views/pages/` (`home`, `how-it-works`, `pricing`, `faq`, `contact`, `privacy`), styled by `public/site.css` (same palette and fonts as the app; light and dark). `sitePage(key, req, notice)` in `server.js` fills `{{BUY_URL}}`, `{{EXAMPLE_URL}}`, `{{BASE}}`, `{{ON_<key>}}` (current menu item), `{{AI_NOTE}}` (privacy, only when AI is on) and an optional notice. The footer carries the "not legal advice" disclaimer. There is no Terms page yet.

Your report is ready", a big **Start the report** (`/app`; **Back to your report** → `/app?paid=1` when `from=app`), the personal link `<base>/?access=RPT-…` with **Copy**, **Share…** (Web Share API, where available), **WhatsApp**, **Text message** (`sms:`) and **Email** (`mailto:`, opens the phone's mail app or Outlook) worded for a tenant, "Keep this link: it’s your access to this report", and a receipt. `noindex` and `Disallow: /buy/done` in robots.txt. `GET /buy/cancel` → `/buy?…cancelled=1`. `POST /api/buy/webhook` only nudges a re-check with SumUp.
- First time a purchase is paid (`settle()`): ntfy alert "Report sold: £30" (`reports.notifyOwner`), analytics `report_purchase` with its value, and, with `RESEND_API_KEY` and an email given, the link and a receipt emailed to the buyer.
- A purchase token is checked locally (`purchases.access()`, before anything else in `checkAccess()` after access codes): valid while unused. When `POST /api/reports` stores a report with it (201), `purchases.markUsed()` marks it used. The same browser (cookie) can still open the app and see and send that report (`state.submittedId`); anyone else with the link gets the home page with "already been used" (402), and pasting it is refused.
- `/admin` has "💷 Report purchases" (sold, revenue, not used yet, started-not-paid; each with name/email, time, provider reference, used or not, and the link in a box to copy and resend).
- **Older paid links** (sold before `/buy`, by another system) keep working silently: a token that isn't an access code or an `RPT-` purchase is checked at `LEGACY_ACCESS_URL/api/public/diy-access/:token` (falls back to `FIXFLOW_URL`, then the old default; cached 5 minutes; let in if that system can't be reached) and marked used there (`…/used`) after its report is stored. Nothing else goes there: no PDFs, no emails, no branding.
- `/` is always the website's home page, for everyone, the owner and people with access included (`paywallPage()`; HTTP 402 with a notice for a bad link or code). The app is at `/app`. A link or code at `/?access=` sets the cookie (HttpOnly, 200 days) and redirects to `/app`. `/?from=<key>` links are redirected to `/app?from=<key>`. `/api/assess` and `POST /api/reports` need a valid token. `BUY_URL` in `server.js` is `/buy` (`{{BUY_URL}}` in the views; `buy` in `/api/access` and 402 answers).
- The owner needs no token: while signed in to `/admin` on that device (`reports.isOwner(req)`), both paywall checks let them through. The admin page has an **Open the app** button (`/app`). Owner reports aren't marked used.
- **Access code** (never called "free" anywhere): one shared code, `2830` to start with, that the owner gives to anyone who may use the app without paying, for any number of reports. It is shown and changed on `/admin` (`POST /admin/code`, same-origin; 4–20 letters or numbers) and kept in `REPORTS_DIR/access-code.json` with a random secret and a use count. Typed on the home or buy page (any case or spacing) or sent as `/?access=CODE`, it becomes the cookie `SHARED-<HMAC of the code>`, so the cookie can't be guessed and changing the code ends every earlier one. Wrong codes are limited to 10 per IP per 15 minutes. One-off codes made before (`DIY-`/`FREE-XXXX-XXXX`, `REPORTS_DIR/access-codes.json`, one report each) still work and are listed with Delete, but no new ones are made. All codes are checked locally (`reports.canonicalCode()` / `codeAccess()` / `useCode()`).
- **Check-in links for tenants** (agent links; `/admin` → "🏢 Check-in links for tenants"; `reports.js` `agentsHTML()`, `POST /admin/agents` with a name, `POST /admin/agents/:id/delete`, same-origin): a named link per estate agent or landlord, `/?access=AGT-<24 url-safe chars>&start=checkin`, that they send to their tenants so each can do their own check-in: it opens straight on a new check-in (the server keeps `start=checkin` on the redirect to `/app`, also for the signed-in owner; the app then sets localStorage `diyCheckinOnly`, so on that phone the type is fixed to Check-In and "Start from an earlier report" is hidden: `checkinOnly()`), and lets them use the app without paying or typing a code, for any number of reports, until the owner removes it (then `codeAccess()` answers `removed` and the link shows "no longer active"). It works like the shared code: the token becomes the `diy_access` cookie, logins and reports go in the access code activity as "agent link: <name>", each report adds to its count (`uses`, `lastUsedAt`, `lastUsedFor`), and floor plans are free with it. Kept in `REPORTS_DIR/agent-links.json`. A link may also carry the property, `&address=<one line, URL-encoded>` (Fixflow adds each tenancy's address to its welcome / DIY emails): the server keeps it on the redirect to `/app` (200 characters max), and the app fills the address fields from it (`splitAddressLine()` → `setAddressFields()`, country set to the UK when it ends in a UK postcode, `picked`), still editable — the setup screen still asks the tenant to check it reads as on the tenancy agreement.
- **Access code activity** on `/admin` ("Who has used the access code"): each time someone gets in with a code (`reports.codeLogin()`, once per device: not when the cookie already holds it) and each report made with one (`useCode(…, req)`), with the time, device (from the user agent, `deviceName()`) and code. Kept in `REPORTS_DIR/access-log.json` (last 300, `seenAt`). Entries since the owner last opened `/admin` are marked New, with a 🔔 banner at the top; opening the page marks them seen.
- **Link previews and search engines**: robots (WhatsApp, iMessage/Facebook, Slack, Telegram, Google…, `PREVIEW_BOT` in `server.js`) get the website page they asked for, and the home page (HTTP 200) for any other address, including `?access=` links, so they never count as an access-code login.
- Environment: `DIY_PAYWALL=off` switches the lock off; the card provider variables are under Environment variables.

## Environment variables (set in Railway → Variables)

- `ANTHROPIC_API_KEY`: enables `/api/assess`. Without it `/api/status` reports `ai:false` and the tenant picks each condition by hand.
- `ANTHROPIC_MODEL`: optional. Defaults to `claude-opus-5-5` (sent with `output_config.effort: 'low'`, `max_tokens: 16000`, and the server-side refusal fallback `fallbacks: 'default'` on the beta endpoint). `claude-haiku-5-5` is much cheaper per photo.
- `AI_FREE_DAILY`: optional. AI suggestions for people who haven't paid yet are limited to 300 photos per IP per day and this many photos per day for the whole site (default 3000).
- **AI is the selling point**: the website and app wording about AI (between `<!--AI-->` and `<!--/AI-->` in `views/pages/`, with `<!--NOAI-->` alternatives; the app's start screen when `aiEnabled`) only appears while `ANTHROPIC_API_KEY` is set, so the site never claims AI that isn't running.
- `IDEAL_POSTCODES_KEY` (preferred) or `GETADDRESS_API_KEY`: switch on the postcode lookup (see Postcode lookup). The key stays on the server. Ideal Postcodes: `GET /v1/postcodes/:postcode` (1 lookup per postcode). getAddress.io: Autocomplete with `all=true` lists the addresses, `/get/:id` gives the picked one's parts. Without either, the address is typed by hand. `ADDRESS_API_BASE` is for tests only (points both providers at a mock server).
- **Free postcode lookup and EPC search, no keys needed** (`epcweb.js`): the public "Find an energy certificate" site (`find-energy-certificate.service.gov.uk/find-a-certificate/search-by-postcode`) is read by postcode and lists every domestic certificate there (address, rating, valid-until date, certificate number; cached 6 h). `address.js` uses it (provider `epc-web`) when there are no `EPC_API_EMAIL`/`EPC_API_KEY`, and the landlord dashboard's EPC search falls back to it (`epcLookupWeb()`). With the register API keys set, the `epc` provider (`GET $EPC_API_BASE/domestic/search?postcode=`) is used instead. Either way one entry per home (newest certificate), split by `epcParts()` into houseNo / building / road / town. Homes that have never had an EPC aren't listed: the person types the address. Providers are tried in turn (Ideal Postcodes, EPC, getAddress.io). If the government changes that page's layout, the regex in `epcweb.js` needs updating.
- `ADMIN_PASSWORD`: the password for `/admin`. Without it `/admin` stays locked (reports are still received and stored).
- `RESEND_API_KEY`: also sends landlord reminders, password-reset links, and each `/buy` buyer's link and receipt (when they gave an email). With `REPORT_TO_EMAIL`, emails each sent report there (resend.com). Without them reports are still marked sent and wait on `/admin`, with the ntfy alert.
- `REPORT_TO_EMAIL`: optional, no default: where each sent report is emailed (the owner's own address). `REPORT_FROM_EMAIL`: optional sender on a domain verified in Resend (e.g. `DIY Inventory <reports@diyinventory.co.uk>`); the default `DIY Inventory <onboarding@resend.dev>` only delivers to the Resend account's own address, so buyers' receipts need a verified domain.
- Card payments for `/buy` and floor plans (`payments.js`): `SUMUP_API_KEY` + `SUMUP_MERCHANT_CODE` (SumUp hosted checkout), or `STRIPE_SECRET_KEY` (Stripe Checkout); the first configured is used, `PAYMENT_PROVIDER` (or the older `FLOORPLAN_PROVIDER`) = `sumup|stripe` picks one. `SUMUP_API_BASE`, `STRIPE_API_BASE`, `RESEND_API_BASE`: tests only (point at a mock).
- `LEGACY_ACCESS_URL`: optional; where older paid links (sold before `/buy`) are still checked. Falls back to `FIXFLOW_URL`, then to the old system's address. Only that check and the "used" notice go there.
- `NTFY_TOPIC`: a phone alert (free ntfy app, ntfy.sh) the first time each report is sent by the tenant, with the address, who sent it and a link to the PDF. Subscribe to the topic in the ntfy app. `NTFY_SERVER` optional, defaults to `https://ntfy.sh`.
- `REPORTS_DIR`: optional override of where reports are stored. On Railway, reports need the volume attached to this service, or they are lost on the next deploy.
- **Domain and DNS**: diyinventory.co.uk is registered at GoDaddy, but its DNS is on **Cloudflare** (free plan; nameservers anita/clint.ns.cloudflare.com), proxied (orange cloud) for both `@` (CNAME → the Railway target for the bare domain) and `www` (CNAME → the Railway target for www), SSL/TLS mode **Full**, Always Use HTTPS on. Cloudflare's own certificate is what visitors and Google see; this was set up because Railway's Let's Encrypt certificate for www was stuck behind a rate limit and Google couldn't fetch the site. Keep the `google-site-verification` and `_railway-verify` TXT records. Don't switch the records to DNS only (grey cloud) or SSL to Flexible (redirect loop). Both hostnames are custom domains on the Railway service (port 8080). The service runs in Railway's EU West (Amsterdam) region (`europe-west4-drams3a`), moved from US West because HM Land Registry refused requests from the US (HTTP 403); the volume moved with it.
- `PUBLIC_URL`: the site's public address, `https://diyinventory.co.uk` once that domain is connected in Railway. Used for canonical URLs, the sitemap, IndexNow and links in alerts; the `www.` form of it (or the bare form, if it's the `www.` one) redirects there with a 301.
- `GOOGLE_SITE_VERIFICATION`, `BING_SITE_VERIFICATION`: optional; the content values from Google Search Console / Bing Webmaster Tools.
- `EPC_API_EMAIL`, `EPC_API_KEY`: the free EPC register API key (register at epc.opendatacommunities.org) for the landlord area's automatic EPC search. Without them landlords enter the EPC by hand. `EPC_API_BASE`: optional, switches the register's address (default `https://epc.opendatacommunities.org/api/v1`); `EPC_API_TOKEN`: optional bearer token instead of email + key, for a newer service.
- `LEADS_KEY`: the shared key (16+ characters) the microsites send with their bookings to `POST /api/leads`; set the same value as `LEADS_KEY` in each Cloudflare Pages project. Without it the endpoint answers 503.
- `LANDLORD_REMINDERS=off`: optional, stops the landlord reminder job.
- `DRAFTS_MAX_MB`: optional cap for online backups (0 or unset = no cap). `DRAFTS_RESERVE_MB`: free space kept on the volume for finished reports (default 300). Backups are never deleted to make room; new ones pause instead.
- `SUMUP_API_KEY` + `SUMUP_MERCHANT_CODE`: card payments for floor plans through SumUp's hosted checkout (preferred). Or `STRIPE_SECRET_KEY` for Stripe Checkout. `FLOORPLAN_PROVIDER=sumup|stripe` picks one when both are set. Without either, Buy explains that card payments aren't switched on yet (the owner can still download). `SUMUP_API_BASE` / `STRIPE_API_BASE` exist only to point tests at a local mock.
- `PORT` is set by Railway. Do not set it.

## Rules (must never regress)

1. Every checklist item that is not marked N/A needs at least one photo before its room can be completed.
2. Every room needs a minimum of 8 photos (`MIN_PHOTOS`). Marking an item not applicable must never bring a room's requirement below 8. The requirement is `max(active items, 8)`. The front door item is mandatory and cannot be marked N/A.
   A room can have at most `MAX_PHOTOS` (25) photos (`roomMaxPhotos()`). To keep every room completable, `roomPhotoSpace(room, item)` keeps one free slot for each other item still without a photo, and a room can have at most 25 items in use (adding an item or un-ticking N/A beyond that is refused). `addPhotoFiles()` and the camera enforce it; `notice()` explains why.
3. Every photo has the date and time burned into the image pixels at capture (`stampPhoto` draws it onto the canvas before encoding). A caption or metadata alone is not enough.
4. The report cannot be finished or produced without a signature drawn on the signature pad and the honesty declaration confirmed. `updateFinishButtonState()` / `completeReport()` enforce this.

## Testing

Any change to `public/index.html` must pass both of these before it is committed:

1. **Syntax:** extract the inline `<script>` and run `node --check` on it:
   ```sh
   node -e "const h=require('fs').readFileSync('public/index.html','utf8');require('fs').writeFileSync('/tmp/a.js',[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]).join('\n'))" && node --check /tmp/a.js
   ```
2. **PDF:** a jsdom run of `buildPdfBlob`. Load `public/index.html` in jsdom with the jsPDF UMD inlined in place of the CDN tag, stub `fetch` for the `/api/*` endpoints and stub canvas/Image, fill every room with photos and conditions, add the declaration and signature, then call `buildPdfBlob(state)`. Confirm it resolves, every page is A4 landscape (841.89 × 595.28 pt), and the rules above still hold.

For server changes: `npm install && npm start`, then `curl` `/`, `/healthz` and `/api/status`.
