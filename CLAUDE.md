# CLAUDE.md

**DIY Inventory**: property inventories, check-ins, check-outs and inspections done on a phone, for tenants, landlords and small agencies (£29.99 per report since Nov 2026, was £30; no subscription; `purchases.js` `PRICE`/`PENCE` = 29.99/2999, a purchase is verified against the amount it was created with). **The business does not charge VAT: never add or mention VAT anywhere (prices, totals, JSON-LD, emails, the app).** The app and the PDF carry no agency name. The report itself never says "DIY Inventory" next to its type (the owner: don't call it a "DIY checkout" on the report): its cover shows the logo mark and "CHECK-OUT REPORT", each page's header "Check-Out report" and the address, and the signed acknowledgement page's footer the same, and each report is titled after its property: `reportTitle()` → "Check-In – 5 Dudley Court, London W1H 5QA" (or Check-Out, or Inspection for interim and renewal inspections; `inspectionKind()`). The managing agent field is optional and blank by default; it only appears on the PDF cover when filled in. Deployed on Railway from this repo (`npm start`, health check `/healthz`).

## Layout

- `public/index.html` is the whole client: HTML, CSS and one inline `<script>`. There is no build step, no bundler and no framework. Edit the file directly.
  - jsPDF 2.5.1 is loaded from cdnjs as a UMD script (`window.jspdf.jsPDF`). `buildPdfBlob(state, onProgress)` builds the report in the browser (A4 landscape, clerk report format).
  - The draft is kept in IndexedDB on the tenant's device. When a report is finished, `submitReport()` quietly saves a copy of the PDF with `POST /api/reports` (once per report: `state.submittedId`; retried when back online), so it is never lost. Finishing (signed and declared) then sends it straight away with `sendToAgent()` → `POST /api/reports/:id/send`, which marks it sent (`state.sentAt`), alerts the owner (ntfy) and, if `REPORT_TO_EMAIL` is set, emails it there. No extra tap is needed: the finished screen's button only shows the progress, or **Try sending again** if it failed; it also retries when the connection returns or the report is reopened. Nothing else is stored on the server.
  - The PDF is delivered as a plain browser download (object URL + `<a download>`). Do not add `claude.*` / `window.claude` calls. The client only talks to this server's `/api/*` endpoints.
  - `preparePdf()` builds the PDF once per finished report and keeps it, so `savePdf()` / `openPdf()` / `sharePdf()` run straight from the tap (phones block downloads that start after the async build). Share uses the Web Share API only where `navigator.canShare` accepts files. A finished report stays in IndexedDB and reopens on the done screen until a new inspection is started.
  - Every photo in the PDF (cover, keys, meters, rooms) is drawn uncropped with `drawFitted()` from a smaller copy (`shrinkPhoto()`: 900 px, 1400 px on the cover). There are no full-size pages in the PDF: each photo, and its View link in the "Index of photographs" at the end, links to `/p/<photoKey>/<n>`, which shows it full size. `photoKey` is random per report (`ensurePhotoKey()`), `n` is the photo's order in the PDF; `buildPdfBlob(state, onProgress, out)` returns that list in `out.photos`, and `submitReport()` uploads the full-size photos after the PDF (`uploadPhotos()`, `state.photosUploaded`).
- Home-screen icon: `public/icons/` (drawn in `icon.svg`, exported to `apple-touch-icon.png` 180, `icon-192.png`, `icon-512.png`, `favicon-32.png`) and `public/manifest.webmanifest` (name "DIY Inventory", `display: browser` so it opens in the normal browser, keeping the camera and PDF downloads as they are). Re-export the PNGs if `icon.svg` changes.

## Paid access

**Free to start, pay at the end.** Anyone can open the app at `/app` (the website's **Start free** buttons; the home-screen icon's `start_url`) and do a whole report. The setup screen says up front that it is free to start and £29.99 to download (`.price-note`), and offers landlords **Pay now · £29.99** (`.pay-first`, `/buy?for=tenant`, same tab) so they can send the tenant a paid link. The setup form is saved on the phone as it's typed (`saveSetupDraft()` → localStorage `diySetupDraft`, restored on load, cleared when the inspection starts or is discarded); after that the draft lives in IndexedDB and online backup as before. The finished screen is locked until paid (`reportUnlocked()`: a report already stored, or `GET /api/access` says this browser has access): instead of Download / Send / sign-off / next report it shows `payCardHTML()`, with **Pay £29.99** (`accessUi.buy` + `?from=app`, **same tab**: the report is safe in IndexedDB), **I’ve paid, check again**, and a box to paste a report link or an access code (`unlockReport()` → `POST /api/access`, which accepts a full `?access=` link, a token or a code, sets the `diy_access` cookie, and counts wrong tries like the home page). After paying, the buyer comes back to `/app?paid=1`; boot strips it, re-checks `/api/access` and the finished screen unlocks by itself. Every finished report still reaches the owner: when the finished screen is locked, `sendUnpaidCopy()` uploads the PDF with `X-Report-Unpaid: 1` (the only way `POST /api/reports` is allowed without access; stored with `unpaid: true`, answers 202, unlocks nothing; `state.unpaidId`), shown on `/admin` as "Not paid yet"; when the paid copy arrives (same ref + finish time) `storeReport()` upgrades it in place (`paidAt`) and answers 201, so the paid link is marked used then. `/admin` also lists, from the online backup, every report finished on a phone whose PDF never arrived ("Finished on the phone · PDF not received", `drafts.finishedOnly()`, View opens the backup). If the PDF build or upload fails on a phone, the app posts the reason to `POST /api/report-problem` (`reportProblem()`), logged as "report not sent from a phone: …". A send cut off by the phone (Share or Download straight after finishing puts the page in the background and iOS stops the upload; this lost a tenant-link report on 30 Oct 2026) is retried by `resumeSending()` when the page is visible again (`visibilitychange`, `pageshow`) and every 30 s on the finished screen (a send stuck over 60 s is restarted). **Server fallback**: `drafts.js` `rescue()` (every 2 minutes) takes any backup finished more than 5 minutes ago with no stored report, waits until all its photos have arrived (30 minutes at most), builds the report on the server from the backup with **the app's own `buildPdfBlob()`** (`render-backup.js`: `public/index.html` run in jsdom in a child process, jsPDF 2.5.1 and floorplan.js inlined from node_modules/public, the backup's photos put back from their files, gaps filled from `defaultState()` / `makeRoom()`; no canvas on the server, so photos go in full size and the signature as its PNG; comparison photos fetched from the web are left out), so it looks exactly like the phone's (the owner: reports must not differ); only if that fails, the simpler `backup-pdf.js` `buildFromBackup()` (pdf-lib; cover, rooms as cards, linked photos, index of photographs; it says it was made from the backup), stores it (`source: 'backup'`, unpaid unless the backup's cookie had a valid link or code: `s._access` via `hasAccess()`), marks it sent, alerts and emails the owner like any sent report (`fromBackup()` in reports.js), and records `s._serverReportId`. If the phone's own PDF arrives later it replaces the server-made one in place (`replacedBackupAt`). The PDF is built on the phone, so the lock is in the app, not on the file. **Chunked upload** (`postReportPdf()` in the app): a PDF over 2 MB goes up in 2 MB pieces (`PUT /api/report-chunks/<upload>/<n>`, each retried up to 6 times; `GET /api/report-chunks/<upload>` lists the pieces already there, so a broken upload carries on; the upload id is per PDF blob), then `POST /api/reports` with `X-Report-Upload`, `-Chunks`, `-Size` and no body: the server joins the pieces (`assembled()`, 409 with the missing ones) and stores it exactly as before (same paywall check and marking used). Pieces live in `REPORTS_DIR/chunks/` (≤ 4 MB each, 1.5 GB in all, removed once stored or after a day). Added after a 48 MB report kept failing from an iPhone on mobile data (30 Oct and 6 Nov 2026). Full-size photos go 2 per request, each retried. **Online link** (`/report/<photoKey>`, noindex, `Disallow: /report/`): the report to view (PDF in the page on computers) and download (`/report/<key>.pdf`, `?download=1`; the signed copy once there is one), with Share and, when there's data, "Check and sign it"; paid reports only (404 otherwise). On `/admin` each paid report has **Online** and **Copy link** (or **Make online link** for one without a key); on the phone's finished screen "View it online" (Share/Copy); the email copies link to it. **Copies by email** (`deliverCopies()` in reports.js, from `POST /api/reports/:id/send` and from `fromBackup()`): once a report is paid for, it is emailed (PDF attached, or a link to `/sign/<key>/report.pdf` above 28 MB, plus the sign-off link) to the person who did it (the optional **Email me a copy** field on the sign-off screen, `state.meta.copyEmail`, sent in the report's meta) and to the buyer's email from `/buy` (`purchases.emailFor(token)`), and, when an agent link was used, to that link's email (set on `/admin` → Tenant links, when making it or with Save on each link; `r.agentId`/`agentName`). Each address once (`r.copies`). **Sent automatically once paid** (the owner asked): the person who did it and whoever paid (`knownTargets(r)` = `emailsForReport()` entries “did the report” / “paid for it”, so a purchase matched only by name or address counts too) get it from `deliverCopies()`, and `copySweep()` (90 s after start, then every 30 min) retries any paid report of the last 30 days whose copies haven't gone. **Record of every email**: each Reports row has “✉ Emailed N times · last <date>” (`sentLog()`: copies after payment, links sent from admin, the owner's copy; open it for each time, address and kind); never while unpaid; needs `RESEND_API_KEY` and a verified `REPORT_FROM_EMAIL` (resend.dev only delivers to the Resend account's own address). ## Environment variables (set in Railway → Variables)

- `ANTHROPIC_API_KEY`: enables `/api/assess`. Without it `/api/status` reports `ai:false` and the tenant picks each condition by hand.
- `ANTHROPIC_MODEL`: optional. Defaults to `claude-opus-5-5` (sent with `output_config.effort: 'low'`, `max_tokens: 16000`, and the server-side refusal fallback `fallbacks: 'default'` on the beta endpoint). `claude-haiku-5-5` is much cheaper per photo.
- `AI_FREE_DAILY`: optional. AI suggestions for people who haven't paid yet are limited to 300 photos per IP per day and this many photos per day for the whole site (default 3000).
- **AI is the selling point**: the website and app wording about AI (between `<!--AI-->` and `<!--/AI-->` in `views/pages/`, with `<!--NOAI-->` alternatives; the app's start screen when `aiEnabled`) only appears while `ANTHROPIC_API_KEY` is set, so the site never claims AI that isn't running.
- `IDEAL_POSTCODES_KEY` (preferred) or `GETADDRESS_API_KEY`: switch on the postcode lookup (see Postcode lookup). The key stays on the server. Ideal Postcodes: `GET /v1/postcodes/:postcode` (1 lookup per postcode). getAddress.io: Autocomplete with `all=true` lists the addresses, `/get/:id` gives the picked one's parts. Without either, the address is typed by hand. `ADDRESS_API_BASE` is for tests only (points both providers at a mock server).
- **Free postcode lookup and EPC search, no keys needed** (`epcweb.js`): the public "Find an energy certificate" site (`find-energy-certificate.service.gov.uk/find-a-certificate/search-by-postcode`) is read by postcode and lists every domestic certificate there (address, rating, valid-until date, certificate number; cached 6 h). `address.js` uses it (provider `epc-web`) when there are no `EPC_API_EMAIL`/`EPC_API_KEY`, and the landlord dashboard's EPC search falls back to it (`epcLookupWeb()`). With the register API keys set, the `epc` provider (`GET $EPC_API_BASE/domestic/search?postcode=`) is used instead. Either way one entry per home (newest certificate), split by `epcParts()` into houseNo / building / road / town. Homes that have never had an EPC aren't listed: the person types the address. Providers are tried in turn (Ideal Postcodes, EPC, getAddress.io). If the government changes that page's layout, the regex in `epcweb.js` needs updating.
- `ADMIN_PASSWORD`: the password for `/admin`. Without it `/admin` stays locked (reports are still received and stored).
- `RESEND_API_KEY` (set Nov 2026): `/admin` → Overview → **Email** shows whether it is on, the from and copy addresses, and **Send a test email** (`POST /admin/test-email`, shows Resend's own answer, e.g. domain not verified). Also sends landlord reminders, password-reset links, and each `/buy` buyer's link and receipt (when they gave an email). With `REPORT_TO_EMAIL`, emails each sent report there (resend.com). Without them reports are still marked sent and wait on `/admin`, with the ntfy alert.

- `LEGACY_ACCESS_URL`: optional; where older paid links (sold before `/buy`) are still checked. Falls back to `FIXFLOW_URL`, then to the old system's address. Only that check and the "used" notice go there.
- `NTFY_TOPIC`: a phone alert (free ntfy app, ntfy.sh) the first time each report is sent by the tenant, with the address, who sent it and a link to the PDF. Subscribe to the topic in the ntfy app. `NTFY_SERVER` optional, defaults to `https://ntfy.sh`.

## Rules (must never regress)

1. Every checklist item that is not marked N/A needs at least one photo before its room can be completed.
2. Every room needs a minimum of 8 photos (`MIN_PHOTOS`). Marking an item not applicable must never bring a room's requirement below 8. The requirement is `max(active items, 8)`. The front door item is mandatory and cannot be marked N/A.
   A room can have at most `MAX_PHOTOS` (25) photos (`roomMaxPhotos()`). To keep every room completable, `roomPhotoSpace(room, item)` keeps one free slot for each other item still without a photo, and a room can have at most 25 items in use (adding an item or un-ticking N/A beyond that is refused). `addPhotoFiles()` and the camera enforce it; `notice()` explains why.
3. Every photo has the date and time burned into the image pixels at capture (`stampPhoto` draws it onto the canvas before encoding). A caption or metadata alone is not enough.
4. The report cannot be finished or produced without a signature drawn on the signature pad and the honesty declaration confirmed. `updateFinishButtonState()` / `completeReport()` enforce this.

## Testing

Any change to `public/index.html` must pass both of these before it is committed:

1. **Syntax:** extract the inline `<script>` and run `node --check` on it:
   ```sh
   node -e "const h=require('fs').readFileSync('public/index.html','utf8');require('fs').writeFileSync('/tmp/a.js',[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]).join('\n'))" && node --check /tmp/a.js
   ```
2. **PDF:** a jsdom run of `buildPdfBlob`. Load `public/index.html` in jsdom with the jsPDF UMD inlined in place of the CDN tag, stub `fetch` for the `/api/*` endpoints and stub canvas/Image, fill every room with photos and conditions, add the declaration and signature, then call `buildPdfBlob(state)`. Confirm it resolves, every page is A4 landscape (841.89 × 595.28 pt), and the rules above still hold.

For server changes: `npm install && npm start`, then `curl` `/`, `/healthz` and `/api/status`.
